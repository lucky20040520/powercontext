## 4. 与题目要求的对应

| 题目要求 | 验证证据 |
|---|---|
| 根据开发任务提供当前有效的规格、相关代码和测试 | 阶段 1/3/5：上下文只含 active 规格与相关代码/测试 |
| 判断哪些决策已经失效 | 阶段 3：规格升级后 DEC-001/002 级联失效并警示 |
| 先前验证是否仍适用于当前代码 | 阶段 2：代码变更 → STALE；阶段 4：契约变更 → INVALID |
| 跨会话和任务交接 | 阶段 5：快照导出/导入，上下文一致 |
| 通过实际代码修改验证效果 | 阶段 2/4 真实读写代码与测试文件，全部断言通过 |

## 5. 已知边界（如实说明）

- 关键词匹配基于词面（中文 2/3-gram + 英文标识符），不做语义理解；
  无关任务会得到空规格集 + 警示，不会误带规格。
- 符号提取为正则级（from-import + HTTP 端点），不解析 AST；
  足以支撑“契约符号缺失 → 验证失效”的判定。
- 与 PowerContext Server 的桥接为可选增强：本机未启动 Server 时
  验证了自动降级路径（`is_available()=False` 不阻塞主流程）。
