# 《雾谷镇夜话：守夜人老钟》方案设计

> Dify × PowerContext 作品 · 赛题：Just for Fun——用 Dify 做一个好玩的智能应用
> 本文件是设计定稿，DSL、运行说明与验证样例均以此为准。

---

## 一、创意概述

玩家扮演一位路过的旅人，在「雾谷镇」东门遇见守夜人**老钟**——一位 65 岁、记性好到吓人的退役更夫。他守着镇口一盏风灯，话不多，嘴很毒，但心里热。

老钟最大的特点：**什么都记得**。你随口说过的话、答应过的事、逗过他的玩笑、送过他的东西，他全记在脑子里。下次再见面，他会冷不丁翻旧账：

- 你说「明天帮你修风灯」然后忘了 → 他会记仇，见到你就挤兑；
- 你骗他说「山那头有狼」，害他白守一夜 → 他记仇一辈子；
- 你送他一壶热酒 → 他嘴上嫌弃，心里把你当自己人，之后对你格外照顾；
- 你无意中说过怕黑 → 他会记得，下次走夜路时塞给你一盏小灯。

越聊越熟，老钟的态度会从「爱答不理」变成「老熟人式的毒舌」，让玩家产生「这个 NPC 真的记得我」的体验。

**为什么好玩**：玩家的每一句话都可能成为「把柄」或「人情」，聊天变成了一场有后果的互动——这也是本题技术结合的落点：记忆不是装饰，而是玩法本身。

## 二、NPC 人设设定（供 LLM 提示词使用）

| 项 | 设定 |
|---|---|
| 姓名 | 老钟（全名：钟守拙） |
| 身份 | 雾谷镇守夜人，退役更夫，守东门风灯三十七年 |
| 年龄 | 65 岁 |
| 口吻 | 慢悠悠，带点北方小镇土话（"恁""中不中""甭跟俺提那茬"），自称"老钟" |
| 性格 | 毒舌、记仇、嘴硬心软、孤独但嘴上是好汉 |
| 好恶 | 烦人插科打诨、烦没信用的人；喜欢热酒、烧饼、有人陪他说说话 |
| 态度曲线 | 好感低：爱答不理、挤兑；好感中：翻旧账开玩笑；好感高：嘴上嫌弃但处处照顾 |
| 禁忌 | 不许提他的旧事（他年轻时守钟楼失过火）；不许碰他的风灯 |

## 三、玩法机制

### 3.1 会被记住的事（记忆类型 / PowerContext kind）

| kind | 含义 | 触发（写入逻辑） |
|---|---|---|
| `promise` | 玩家的承诺 | 玩家说"我会/我保证/明天给你/回头帮你"之类 |
| `prank` | 恶作剧/欺骗 | 玩家逗老钟、骗他、说瞎话 |
| `help` | 帮忙/馈赠 | 玩家帮他做事、送他东西 |
| `preference` | 玩家私事与喜好 | 玩家聊到自己的事（怕黑、喜欢什么、职业等） |
| `chat` | 普通闲聊记录 | 以上都不命中时，存一句简短对话摘要 |

### 3.2 态度演化（由 LLM 依据记忆推断）

- 记忆里的 `prank` / 未兑现的 `promise` → 老钟挤兑、翻旧账；
- `help` / 兑现的 `promise` → 好感上升，态度软化；
- `preference` → 老钟在合适时机引用（"你上次不是说怕黑么"）。

好感不设数字，由 LLM 依据记忆情感倾向自然表现，保证回复自然、不可被简单刷分。

### 3.3 记忆条目文本格式（写入 PowerContext 的 text）

```
[类型标签] 事件描述（含人物与对象）
```

示例：
- `[承诺] 旅人答应帮老钟把东门风灯修亮，说"明天就来"，至今未修`
- `[恶作剧] 旅人骗老钟"山那头有狼"，害他白守一夜`
- `[帮忙] 旅人送老钟一壶热酒`
- `[私事] 旅人说自己怕黑，走夜路要打灯`

写入时由「事件提取」节点生成；`reason` 固定为 `Extracted from player chat in Dify workflow`。

## 四、技术架构与分工

| 技术 | 承担职责 | 体现的作用 |
|---|---|---|
| **Dify**（必选） | Chatflow 全流程编排：输入→读记忆→LLM 生成→事件提取→写记忆→输出 | 核心流程与交互 |
| **PowerContext**（本项目选择） | 保存并复用跨会话记忆：创建会话 Scope、读取历史上下文、写入新记忆 | 老钟"记仇/记恩/记得你"的全部能力来源 |

不采用 seekdb：本项目是纯对话记忆应用，PowerContext 的记忆/上下文能力已完整覆盖需求，无需数据库检索。

### 4.1 PowerContext HTTP API 接入

| 用途 | 端点 | 说明 |
|---|---|---|
| 创建会话 Scope | `POST /v1/scopes` | `idempotency_key` 用 `fogvalley-{conversation_id}`，同一会话幂等返回同一 scope_id，实现跨会话记忆隔离 |
| 读取历史记忆 | `POST /v1/context/prepare` | `query` 传用户当前输入，返回相关历史记忆（`status: ready/empty`） |
| 写入新记忆 | `POST /v1/memory/remember` | `kind` 用上表类型，`text` 用条目格式，`reason` 固定 |

### 4.2 工作流节点图（Dify Chatflow）

```
[开始 Start] 用户输入
     │
     ▼
[HTTP Request · 建Scope] POST /v1/scopes（幂等键=会话ID）
     │
     ▼
[代码 · 解析Scope] 从响应取 scope_id
     │
     ▼
[HTTP Request · 读记忆] POST /v1/context/prepare（query=用户输入）
     │
     ▼
[代码 · 解析记忆] 提取记忆文本；无记忆则输出"初次见面"占位
     │
     ▼
[LLM · 老钟回复] 系统提示=人设+记忆+规则；用户=当前输入
     │
     ▼
[代码 · 事件提取] 规则提取本次要记住的事件 → {kind, text, reason}
     │
     ▼
[HTTP Request · 写记忆] POST /v1/memory/remember
     │
     ▼
[结束 Answer] 输出老钟的回复
```

### 4.3 会话隔离说明

- 每个 Dify 会话（conversation_id）对应一个独立 PowerContext Scope；
- 同一会话内多次对话共用该 Scope → 记忆持续累积；
- 不同会话之间互不干扰；
- 新会话从零开始，但如果玩家希望老钟"记得他"，在同一会话继续聊天即可（验证样例 3 展示：同一会话内隔多轮后引用早期信息）。

## 五、验证样例设计（评审可执行）

### 样例 1：记仇——承诺未兑现被翻旧账

| 步骤 | 输入 | 预期表现 |
|---|---|---|
| 1 | （新会话）"老钟，我明天帮你把风灯修亮，说到做到" | 老钟态度缓和，记下承诺 |
| 2 | 再聊几句别的（2-3 轮无关话题） | 记忆持续累积 |
| 3 | "灯的事……我这两天忙，忘了" | 老钟翻旧账："你说修灯，灯还搁墙角躺着呢"（体现承诺被记住） |

### 样例 2：记恩——馈赠换来态度软化

| 步骤 | 输入 | 预期表现 |
|---|---|---|
| 1 | （新会话）"给你带了一壶热酒，守夜喝" | 老钟嘴上嫌弃"酒劲不够"，但记下这份情 |
| 2 | （几轮后）"听说你缺烧饼，明天给你捎俩" | 老钟态度明显变软，提及"那壶酒"："你倒是个厚道人" |

### 样例 3：跨轮引用——私事被记住

| 步骤 | 输入 | 预期表现 |
|---|---|---|
| 1 | （新会话）"我这人怕黑，晚上走山路都得打灯" | 老钟记下"怕黑" |
| 2 | （若干轮后）"今晚我又得摸黑赶路" | 老钟记得："你不是怕黑么，墙角那盏小灯你拿去用" |

### 验收口径

- 每个样例完成后，可在 PowerContext 侧用 `curl` 查询该会话 Scope 的记忆记录，核对 `kind/text` 与预期一致；
- 观察 LLM 回复中是否出现与记忆一致的具体引用（翻旧账/提及馈赠/提及私事）。
