# 验证记录：PowerContext 记忆闭环实测

> 对应赛题 4.3「验证样例与运行证据」——PowerContext 在应用功能中的实际作用及读写记录。
> 复现脚本：`docs/verify_memory_loop.py`（模拟 Dify 工作流中三个 HTTP 节点的调用序列）。

## 一、验证环境

| 项 | 值 |
|---|---|
| 机器 | Windows 本地（D 盘部署） |
| PowerContext Server | 1.4.2.dev21+g927bb6ee1（`powercontext server run`，127.0.0.1:8000） |
| 存储 | SQLite 默认配置 |
| 鉴权 | 未启用（no-auth，与 DSL 默认一致） |
| 模型 | 本验证不需要推理模型（记忆读写闭环与模型无关） |

## 二、验证步骤与结果（2026-10-28）

### 步骤 1：建 Scope（对应 Dify「建Scope」HTTP 节点）

```json
POST /v1/scopes
{"title": "雾谷镇旅人会话", "summary": "雾谷镇守夜人老钟与旅人的对话记忆（按会话隔离）", "idempotency_key": "fogvalley-demo-conv-001"}
```

**结果**：`scope_id: scp_6bnry3xhmtyyrbzx2c7rn4a3dz`

### 步骤 2：写入记忆（对应 Dify「写记忆」HTTP 节点）

```json
POST /v1/memory/remember
{"scope_id": "scp_6bnry3xhmtyyrbzx2c7rn4a3dz", "kind": "promise",
 "text": "[承诺] 旅人对老钟说：「老钟，明天我帮你把东门的风灯修亮，说到做到」（老钟默默记下）。",
 "reason": "Extracted from player chat in Dify workflow"}
```

**结果**：写入成功，`changed: true`，记录：

```json
{"records": [{"artifact": {"family": "atomic-memory", "artifact_id": "art_56b4fdbec014495faca722b8a3f83d0f", "revision": 1},
               "kind": "promise", "state": "active",
               "text": "[承诺] 旅人对老钟说：「老钟，明天我帮你把东门的风灯修亮，说到做到」（老钟默默记下）。"}]}
```

### 步骤 3：召回记忆（对应 Dify「读记忆」HTTP 节点）

```json
POST /v1/context/prepare
{"scope_id": "scp_6bnry3xhmtyyrbzx2c7rn4a3dz", "query": "修风灯 承诺", "max_bytes": 2000}
```

**结果**：`status: ready`，召回内容：

```
[承诺] 旅人对老钟说：「老钟，明天我帮你把东门的风灯修亮，说到做到」（老钟默默记下）。
```

### 步骤 4：预置演示记忆实测（对应 `scripts/seed_demo_memory.py`，2026-10-28 追加）

为评审提供"老钟记得旧事"的开场演示，脚本写入 4 类记忆：

```
scope_id: scp_67cwh1qsz1pgbs9r84rawwtapy
  [promise] changed=True
  [prank]   changed=True
  [help]    changed=True
  [preference] changed=True
```

**结果**：4 条记忆全部写入成功；召回核对命令（复现）：

```bash
curl -s -X POST http://127.0.0.1:8000/v1/context/prepare -H "Content-Type: application/json" \
  -d '{"scope_id":"scp_67cwh1qsz1pgbs9r84rawwtapy","query":"风灯 热酒 怕黑","max_bytes":3000}'
```

## 三、结论

- PowerContext 的「创建会话 Scope → 写入记忆 → 召回记忆」闭环在真实 Server 上验证通过；
- Dify 工作流中三个 HTTP Request 节点（建Scope / 读记忆 / 写记忆）按上述相同请求构造，`docs/verify_memory_loop.py` 与 DSL 内 Code 节点解析逻辑一致；
- 记忆按会话（idempotency_key=conversation_id）隔离、可写入、可召回，满足作品「老钟记得玩家说过的话」的技术要求。

## 四、说明

- LLM 生成老钟回复（DSL「老钟回复」节点）需真实模型服务，本地验证环境未配置模型 API Key，故该环节在评审环境按 `docs/运行说明.md` 配置模型后验证；
- 本记录仅证明指定技术（PowerContext）在作品中的实际作用与读写链路，完整体验请按运行说明导入 DSL 后实测。
