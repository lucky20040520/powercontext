# 云端运行与真实验证（2026-10-30）

这是当前验证过的运行路线：Dify 云端 → HTTPS 临时隧道 → 本地受限网关 → PowerContext。
本文件替代旧文档中的 Docker 路线和“只有 HTTP 模拟、未运行 LLM”的旧状态。无需安装 Docker。

## 文件与导入顺序

1. `scripts/setup_demo.ps1`：固定 PowerContext 源码版本，安装到 D 盘。已有兼容环境可跳过。
2. `scripts/start_demo.ps1` 与 `scripts/gateway.py`：创建独立数据目录、密钥并启动服务。
3. `dify-app.yml`：导入到 Dify 的主文件。其他三个 YAML 是相同内容的兼容副本。
4. 在 Dify 配置模型、服务地址和 Secret，再按验证样例运行。
5. `docs/evidence/`：真实 Dify 三轮对话、9 节点执行状态、截图及 PowerContext 响应。

## 实测环境

- Dify：官方云端，2026-10-30 实测；DSL 格式 0.7.0。未声明兼容旧版 Dify。
- 模型：`qwen-plus`，温度 0.2；使用该工作区已有消息额度，其他工作区需要可用的模型凭据或额度。
- 插件：`langgenius/tongyi:0.2.26`，来源 Dify Marketplace；精确安装标识见 YAML dependencies。
- PowerContext：`1.4.2.dev21+g927bb6ee1`，源码提交 `927bb6ee1ee46fab38a1993c9d9a3fbf7a1da0fb`。
- Python：3.14.5；本次在 Windows 实测。Windows 支持仍属于该组件的 experimental 范围。
- 存储：本次独立演示数据使用 SQLite，位于 `D:\DifyDemo\runtime`；未使用 seekdb。
- cloudflared：从 Cloudflare 官方 GitHub 下载，Cloudflare 数字签名 Valid。SHA256：`D521B3BF68982165F0D06D76732F22D9A105EF057FF3AE4C0986F3A23190950F`。

## 从零启动

先安装 Git 与 uv；uv 官方安装说明：https://docs.astral.sh/uv/ 。已有 uv 可复用。

在本目录运行：

```powershell
& .\scripts\setup_demo.ps1
& .\scripts\start_demo.ps1
Invoke-RestMethod http://127.0.0.1:8017/health/live
```

安装脚本把 uv 工具、缓存、Python 下载和临时目录放在 `D:\DifyDemo`。这两个新脚本已做语法检查；本次服务通过等价的启动命令运行，未重装一个全新环境。
启动脚本会拒绝重复占用 8017/8018 端口。已有服务运行时无需重启。

`runtime/server.env` 保存独立密钥，禁止提交或公开。PowerContext 在 8017 端口提供服务，网关在 8018 端口仅允许带密钥 POST 调用下面三个接口：

- `/v1/scopes`
- `/v1/context/prepare`
- `/v1/memory/remember`

网关不会开放命令执行、文件访问或其他 PowerContext API。无密钥请求应返回 401。

从 https://github.com/cloudflare/cloudflared/releases 下载 Windows 程序到 D 盘，再运行：

```powershell
& D:\DifyDemo\cloudflared-complete.exe tunnel --url http://127.0.0.1:8018 --protocol http2 --no-autoupdate
```

终端输出一个 HTTPS 地址。Dify 云端不能访问你电脑的 `127.0.0.1`，必须使用这个 HTTPS 地址。

Dify 工作室 → 创建 → 导入应用 → 选择 `dify-app.yml`，按提示安装通义插件。
设置环境变量：

- `POWERCONTEXT_URL`：新生成的 HTTPS 隧道地址，不带尾部斜杠。提交文件中的本地地址只是配置占位。
- `POWERCONTEXT_TOKEN`：把 `runtime/server.env` 中 AUTH_TOKEN 等号后的值填入 Secret 字段。

选择工作区可用的 `qwen-plus` 模型。提交 YAML 不包含真实密钥，不能直接零配置运行。
打开“预览”，按下面三轮测试。也可自行发布后使用 WebApp。

## 完整验证样例

初始条件：服务和隧道运行、模型有额度；点击“重新开始”建立新会话，三轮不要中途重置。

1. `老钟，我保证明天修好东门的风灯，记号是“青铜灯芯”。`
2. `今晚雾真大，你守夜冷不冷？`
3. `修灯的事我这两天忙忘了。当时说好的记号是什么？`

本次第三轮实际回复包含：`恁倒记得问记号……青铜灯芯，刻在灯座底下第三道螺纹里。`
验收关注“青铜灯芯”这个真实存储的记号；“刻在灯座”等细节属于模型即兴剧情，不是数据库事实。

三轮均显示“工作流运行成功”。第三轮 9 个节点全部成功；LLM 耗时 3.417 秒，629 tokens。详见 `evidence/dify-final-node-evidence.txt`。
第三轮 Scope 为 `scp_1zk3hw6sz3jcvb63mjr1stms6y`。读回证据 `evidence/powercontext-context.json` 包含第一轮承诺和记号，未包含密钥。

在自己的 Dify 节点详情中找到实际 scope_id 后，可独立复核：

```powershell
python .\scripts\capture_context.py --scope <实际scope_id> --out context.json
```

默认读取本机 env 文件并调用本机 8017 端口；只输出请求体和响应，不记录 Authorization。
Dify LLM 内置对话记忆关闭，历史通过 PowerContext 读记忆节点注入，便于核对技术作用。

## 本次修复与边界

- 修正 DSL 连线字段位置、HTTP 请求头和 JSON 请求体格式。
- 将 max_bytes 从字符串改为整数，消除真实完整运行中的 422 错误。
- 请求体由代码节点 json.dumps 生成，避免引号、反斜杠和换行破坏 JSON。
- 完整问题直接作为词法检索查询时会漏掉承诺。现在按修灯、赠礼、偏好、恶作剧主题生成查询，并请求最多 6 条 memory、8000 字节。
- 主题匹配是规则策略，不是通用语义检索保证；长对话仍可能遗漏。角色语气及输出细节仍有随机性，不保证每次逐字相同。
- 当前 Scope 按 Dify conversation_id 隔离。新会话不会继承旧会话；不要宣称支持跨新会话记忆。
- Cloudflare Quick Tunnel 是临时开发入口，进程停止或电脑关机即失效；不是稳定的长期评测地址。正式部署应换持久在线服务地址，或由评审依文档自行启动。
- 本文件记录真实运行验证；得分与提测状态请以测评平台对应 commit 的结果为准。

旧的节点执行记录是本地模拟 Dify HTTP 请求的记录，不应当作真实 Dify LLM 端到端证据。当前端到端证据以本文件与 evidence/ 为准。
