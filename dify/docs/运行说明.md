# 《雾谷镇夜话：守夜人老钟》运行说明

> Dify × PowerContext 作品 · 赛题：Just for Fun——用 Dify 做一个好玩的智能应用
> 配套文件：`workflows/雾谷镇夜话_守夜人老钟.yml`（DSL）、`docs/方案设计.md`（设计定稿）、`docs/validate_dsl.py`（DSL 校验脚本）、`scripts/init_powercontext.*`（PowerContext 初始化脚本）

---

## 一、作品创意与玩法

玩家扮演一位赶夜路的旅人，在「雾谷镇」东门遇见守夜人**老钟**——一个 65 岁、记性好到吓人的退役更夫。老钟守着镇口一盏风灯，话不多、嘴很毒，但心里热。

**核心玩法：每一句话都算数。** 老钟会记住你说过的话：

- 你承诺帮他修风灯、然后忘了 → 他会翻旧账挤兑你；
- 你骗他「山那头有狼」害他白守一夜 → 他记仇；
- 你送他一壶热酒 → 他嘴上嫌弃，心里把你当自己人；
- 你无意中说过怕黑 → 他会记住，走夜路时塞给你一盏小灯。

**体验方式**：打开应用后直接与老钟聊天，从「新会话」开始，连续聊几轮，观察老钟如何引用你们之前的对话。开场推荐使用应用内置的建议问题（如"老钟，明天我帮你把风灯修亮"）。

**为什么好玩**：聊天不再是"说过就忘"，玩家的每一句话都可能变成把柄或人情，形成"这个 NPC 真的记得我"的沉浸体验。

## 二、技术分工

| 技术 | 职责 | 实际作用点 |
|---|---|---|
| **Dify**（必选） | Chatflow 全流程编排：输入 → 建 Scope → 读记忆 → LLM 生成回复 → 事件提取 → 写记忆 → 输出 | 核心流程与交互全部由 Dify 完成 |
| **PowerContext**（本题选用） | 会话级记忆存储与召回：`POST /v1/scopes`（建会话 Scope）、`POST /v1/context/prepare`（召回历史）、`POST /v1/memory/remember`（写入新记忆） | 老钟"记得你"的全部能力来源：承诺/恶作剧/馈赠/私事都写入 PowerContext，并在后续对话中被召回、影响回复 |

**技术选型说明**：本项目是纯对话记忆应用，PowerContext 的记忆与上下文能力已完整覆盖需求（Dify + PowerContext 组合，符合题目要求，不额外使用 seekdb）。

**记忆闭环示意**：
```
玩家输入 →（Dify HTTP 节点）建/复用会话 Scope
        →（Dify HTTP 节点）prepare 召回历史记忆
        →（Dify LLM 节点）老钟结合记忆生成回复
        →（Dify Code 节点）规则提取本次事件（承诺/恶作剧/馈赠/私事）
        →（Dify HTTP 节点）remember 写入记忆
        → 输出回复
```

## 三、运行环境与依赖

| 组件 | 版本 / 要求 |
|---|---|
| Dify 社区版 | Docker Compose 部署（Dify 1.x 均可，DSL 版本 0.3.0） |
| PowerContext Server | Python 3.11+、Git、`uv`；分支 `master` |
| LLM 模型 | 任意 Dify 支持的模型供应商（推荐 gpt-4o-mini 或 deepseek-chat），需自备 API Key |
| 网络 | PowerContext 跑在本地 127.0.0.1，无外网要求；LLM 调用需可访问模型服务 |
| 资源 | 建议 4 核 8G 内存；磁盘 20G 以上（Dify 镜像 + 数据） |

## 四、部署步骤（从零到可玩）

### 4.1 部署 PowerContext Server

PowerContext 提供 `cli+server` 安装方式（Windows 支持为 experimental；若 Windows 安装失败，建议在 WSL2/Linux 中执行同样命令）：

```bash
uv tool install --force "powercontext[cli,server] @ git+https://github.com/oceanbase/powercontext.git@master"
powercontext server run
```

保持 Server 运行。在另一个终端检查健康状态（应返回 `ok`）：

```bash
curl --fail --silent http://127.0.0.1:8000/health/live
```

> 默认本地配置使用 SQLite，无需额外数据库；默认不启用鉴权（DSL 按无鉴权对接）。
> 也可以运行 `scripts/init_powercontext.sh`（Linux/WSL）或 `scripts/init_powercontext.ps1`（Windows PowerShell）完成安装、启动与健康检查。

### 4.2 部署 Dify 社区版（Docker）

```bash
git clone https://github.com/langgenius/dify.git
cd dify/docker
cp .env.example .env
docker compose up -d
```

浏览器访问 `http://localhost`，完成初始化（设置管理员账号，等待 1-2 分钟服务就绪）。

### 4.3 配置 LLM 模型

在 Dify 中进入「设置 → 模型供应商」，添加你的模型供应商（如 OpenAI / DeepSeek / 通义等），填入 API Key（如 `<你的API_KEY>`）。配置后确认模型可用（可做一次连通性测试）。

### 4.4 导入应用 DSL

1. Dify 顶部进入「工作室」→「导入 DSL」，选择 `workflows/雾谷镇夜话_守夜人老钟.yml`；
2. 若提示缺少模型插件（`langgenius/openai`），按界面提示安装 openai 插件；或导入后在 LLM 节点改用你已经配置的模型；
3. 应用内的环境变量（可在应用「编排 → 环境变量」中查看/修改）：
   - `POWERCONTEXT_URL`：默认 `http://127.0.0.1:8000`，与 4.1 保持一致即可；
   - `POWERCONTEXT_TOKEN`：默认留空（Server 未启用鉴权）。
4. 若使用其他模型：打开工作流中的「老钟回复」LLM 节点，把模型切换为你的模型。

### 4.5 发布并打开入口

在应用页面点击「发布」。之后两种体验方式任选：

- **调试页**：应用内「预览/调试」对话框直接聊天（推荐评审用）；
- **WebApp**：「发布 → 访问 WebApp」获得一个独立聊天页面链接，可作为作品入口提交。

## 五、验证样例（评审可按此执行）

> 前提：PowerContext 已运行、Dify 应用已导入发布、模型可用。
> 每个样例请点击「**新会话**」从零开始；样例内的多轮对话保持在同一会话中连续进行。

### 样例 1：记仇——承诺未兑现被翻旧账

| 轮次 | 玩家输入 | 预期表现 |
|---|---|---|
| 1 | （新会话）老钟，明天我帮你把东门的风灯修亮，说到做到 | 老钟态度缓和，记住这个承诺（写入 `promise` 记忆） |
| 2 | 你守着灯这么多年，不累吗？ | 老钟闲聊回应（记忆持续累积） |
| 3 | 灯的事……我这两天忙，忘了 | **老钟翻旧账**：提及"你说修灯，灯还搁墙角躺着呢"，明显挤兑 |

**验收要点**：第 3 轮回复中出现与"修灯承诺"一致的引用；PowerContext 侧可核对该会话存在 `[承诺]` 类型记忆。

### 样例 2：记恩——馈赠换来态度软化

| 轮次 | 玩家输入 | 预期表现 |
|---|---|---|
| 1 | （新会话）给你带了一壶热酒，守夜喝 | 老钟嘴上嫌弃（"酒劲不够"），但记下这份情（写入 `help` 记忆） |
| 2 | 听说你缺烧饼，明天给你捎俩 | 老钟态度明显变软，提及"那壶酒"，说你"还算厚道" |

**验收要点**：第 2 轮回复提及第 1 轮的"热酒"；态度较第 1 轮软化。

### 样例 3：跨轮引用——私事被记住

| 轮次 | 玩家输入 | 预期表现 |
|---|---|---|
| 1 | （新会话）我这人怕黑，走夜路都得打灯 | 老钟记下"怕黑"（写入 `preference` 记忆） |
| 2 | 今晚我又得摸黑赶路 | **老钟记得**："你不是怕黑么，墙角那盏小灯你拿去用" |

**验收要点**：第 2 轮回复引用第 1 轮提到的"怕黑"。

### 5.1 记忆核对的辅助方法（开发者/评委可选）

在应用调试日志中查看「建Scope」节点的响应体，得到当前会话的 `scope_id`，然后用 curl 召回该会话记忆：

```bash
curl -s -X POST http://127.0.0.1:8000/v1/context/prepare \
  -H "Content-Type: application/json" \
  -d '{"scope_id":"<scope_id>","query":"承诺","max_bytes":2000}'
```

返回的 `content` 即为该会话被召回的记忆文本，可核对 `[承诺]`、`[帮忙/馈赠]`、`[私事]` 等条目与轮次输入一致。

## 六、已知限制与说明

1. **平台**：PowerContext 在 Windows 上为 experimental 支持，推荐在 Linux / WSL2 运行 Server；Dify 无此限制。
2. **事件提取**：采用关键词规则（DSL 内 Code 节点），复杂/隐晦句式可能归类不准确，但不影响记忆写入与召回主流程。
3. **鉴权**：默认无鉴权部署仅用于本地体验与评测；如需公网部署，请开启 PowerContext Server token 鉴权，并把 token 填入应用环境变量 `POWERCONTEXT_TOKEN`（DSL 已预留；当前版本 HTTP 节点按 no-auth 配置，公网场景请手动切换为 Bearer 鉴权）。
4. **模型成本**：LLM 调用消耗用户自备的模型额度；建议使用 gpt-4o-mini / deepseek-chat 等低价模型。

## 七、配置占位说明

- 本文所有 API Key 均以 `<你的API_KEY>` 占位，未提交任何真实凭据；
- 工作流内的 PowerContext 地址为默认本地值，可按实际环境修改环境变量 `POWERCONTEXT_URL`。
