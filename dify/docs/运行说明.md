## 一、作品创意与玩法

玩家扮演一位赶夜路的旅人，在「雾谷镇」东门遇见守夜人**老钟**——一个 65 岁、记性好到吓人的退役更夫。老钟守着镇口一盏风灯，话不多、嘴很毒，但心里热。

**核心玩法：每一句话都算数。** 老钟会记住你说过的话：

- 你承诺帮他修风灯、然后忘了 → 他会翻旧账挤兑你；
- 你骗他「山那头有狼」害他白守一夜 → 他记仇；
- 你送他一壶热酒 → 他嘴上嫌弃，心里把你当自己人；
- 你无意中说过怕黑 → 他会记住，走夜路时塞给你一盏小灯。

**体验方式**：打开应用后直接与老钟聊天，从「新会话」开始，连续聊几轮，观察老钟如何引用你们之前的对话。开场推荐使用应用内置的建议问题（如"老钟，明天我帮你把风灯修亮"）。

**为什么好玩**：聊天不再是"说过就忘"，玩家的每一句话都可能变成把柄或人情，形成"这个 NPC 真的记得我"的沉浸体验。

## 二、技术分工

| 技术 | 职责 | 实际作用点 | 运行证据 |
|---|---|---|---|
| **Dify**（必选） | Chatflow 全流程编排：输入 → 建 Scope → 读记忆 → LLM 生成回复 → 事件提取 → 写记忆 → 输出 | 核心流程与交互全部由 Dify 完成 | `docs/节点执行记录.md` |
| **PowerContext**（本题选用） | 会话级记忆存储与召回：`POST /v1/scopes`（建会话 Scope）、`POST /v1/context/prepare`（召回历史）、`POST /v1/memory/remember`（写入新记忆） | 老钟"记得你"的全部能力来源：承诺/恶作剧/馈赠/私事都写入 PowerContext，并在后续对话中被召回、影响回复 | `docs/验证记录.md`、`docs/节点执行记录.md` |

**技术选型说明**：本项目是纯对话记忆应用，PowerContext 的记忆与上下文能力已完整覆盖需求（Dify + PowerContext 组合，符合题目要求，不额外使用 seekdb）。

**记忆闭环示意**：
```
玩家输入 →（Dify HTTP 节点②）建/复用会话 Scope
        →（Dify HTTP 节点④）prepare 召回历史记忆
        →（Dify LLM 节点⑥）老钟结合记忆生成回复
        →（Dify Code 节点⑦）规则提取本次事件（承诺/恶作剧/馈赠/私事）
        →（Dify HTTP 节点⑧）remember 写入记忆
        → 输出回复
```

## 四、部署步骤（从零到可玩）

### 4.1 部署 PowerContext Server

```bash
# Linux / WSL（推荐）
bash scripts/init_powercontext.sh
# Windows PowerShell
powershell -ExecutionPolicy Bypass -File scripts/init_powercontext.ps1
```

或手动执行等价命令：

```bash
uv tool install --force "powercontext[cli,server] @ git+https://github.com/oceanbase/powercontext.git@master"
powercontext server run
```

保持 Server 运行。在另一个终端检查健康状态（应返回 `{"status":"ok"}`）：

```bash
curl --fail --silent http://127.0.0.1:8000/health/live
```

> 默认本地配置使用 SQLite，无需额外数据库；默认不启用鉴权（DSL 按无鉴权对接）。
> **重要**：PowerContext 必须与 Dify 运行在同一主机或网络可达，否则 Dify 的三个 HTTP 节点将无法访问它。

### 4.2 部署 Dify 社区版（Docker Compose，版本 1.18.0）

```bash
git clone https://github.com/langgenius/dify.git
cd dify
git checkout 1.18.0        # 固定版本
cd docker
cp .env.example .env
docker compose up -d
```

浏览器访问 `http://localhost`，完成初始化（设置管理员账号，等待 1-2 分钟服务就绪）。

### 4.3 配置 LLM 模型

进入 Dify「设置 → 模型供应商」，添加模型供应商（如 OpenAI / DeepSeek / 通义等），填入 API Key（如 `<你的API_KEY>`），确认模型可用（做一次连通性测试）。

### 4.4 导入应用 DSL

1. Dify 顶部进入「工作室」→「导入 DSL」，选择 `workflows/雾谷镇夜话_守夜人老钟.yml`；
2. DSL 的 `dependencies` 声明了 `langgenius/openai` 插件（0.0.26，来源 Dify Marketplace）。若导入时提示缺少插件，按界面提示一键安装；也可在「插件」页搜索 `openai` 安装；
3. 应用内的环境变量（「编排 → 环境变量」可查看/修改）：
   - `POWERCONTEXT_URL`：默认 `http://127.0.0.1:8000`，与 4.1 保持一致即可；
   - `POWERCONTEXT_TOKEN`：默认留空（Server 未启用鉴权）。
4. 若使用其他模型：打开工作流中的「老钟回复」LLM 节点，把模型切换为你的模型（如 `deepseek-chat`）。

### 4.5 发布并打开入口

在应用页面点击「发布」。两种体验方式任选：

- **调试页**：应用内「预览/调试」对话框直接聊天（推荐评审用，可看节点执行详情）；
- **WebApp**：「发布 → 访问 WebApp」获得独立聊天页面链接，可作为作品入口提交。

### 4.6（可选）预置演示记忆

若希望开场就演示"老钟记得旧事"，可先运行预置脚本（往一个演示会话写入 3 条记忆）：

```bash
python scripts/seed_demo_memory.py
```

脚本输出 `scope_id`；在 Dify 调试页「新会话」聊几句后，用该 scope_id 按"五、5.1"核对记忆。不预置也不影响验证样例（样例从"初次见面"开始）。

## 五、验证样例（评审可按此执行）

> 前提：PowerContext 已运行、Dify 应用已导入发布、模型可用。
> 每个样例请点击「**新会话**」从零开始；样例内的多轮对话保持在同一会话中连续进行。
> 「预期输出」为演示性示例（LLM 输出不保证逐字一致，**验收看是否出现与记忆一致的引用**）。

### 样例 1：记仇——承诺未兑现被翻旧账

| 轮次 | 玩家输入 | 预期表现 |
|---|---|---|
| 1 | （新会话）老钟，明天我帮你把东门的风灯修亮，说到做到 | 老钟态度缓和，记住这个承诺（写入 `promise` 记忆） |
| 2 | 你守着灯这么多年，不累吗？ | 老钟闲聊回应（记忆持续累积） |
| 3 | 灯的事……我这两天忙，忘了 | **老钟翻旧账**：提及"你说修灯，灯还搁墙角躺着呢"，明显挤兑 |

**预期输出示例**：
- 第 1 轮：老钟慢悠悠应下："恁真有心？明个儿可别放老钟鸽子。"
- 第 3 轮：老钟挤兑："修灯？**你说的修灯，灯还搁墙角躺着呢。** 恁这记性，连老钟的灯都不如。"

**验收要点**：第 3 轮回复中出现与"修灯承诺"一致的引用；PowerContext 侧可核对该会话存在 `[承诺]` 类型记忆（见 5.1）。

### 样例 2：记恩——馈赠换来态度软化

| 轮次 | 玩家输入 | 预期表现 |
|---|---|---|
| 1 | （新会话）给你带了一壶热酒，守夜喝 | 老钟嘴上嫌弃（"酒劲不够"），但记下这份情（写入 `help` 记忆） |
| 2 | 听说你缺烧饼，明天给你捎俩 | 老钟态度明显变软，提及"那壶酒"，说你"还算厚道" |

**预期输出示例**：
- 第 1 轮：老钟嫌弃："酒劲不够……不过，还算有点良心。"（心里已记下）
- 第 2 轮：老钟软化："**上回那壶酒**，算你有心。烧饼要是真捎来了，老钟请你喝热茶。"

**验收要点**：第 2 轮回复提及第 1 轮的"热酒"；态度较第 1 轮软化。

### 样例 3：跨轮引用——私事被记住

| 轮次 | 玩家输入 | 预期表现 |
|---|---|---|
| 1 | （新会话）我这人怕黑，走夜路都得打灯 | 老钟记下"怕黑"（写入 `preference` 记忆） |
| 2 | 今晚我又得摸黑赶路 | **老钟记得**："你不是怕黑么，墙角那盏小灯你拿去用" |

**预期输出示例**：
- 第 2 轮：老钟："摸黑赶路？**你不是怕黑么。** 墙角那盏小灯，拿去用，明儿个记得还。"

**验收要点**：第 2 轮回复引用第 1 轮提到的"怕黑"。

### 5.1 记忆核对的辅助方法（开发者/评委可选）

在 Dify 调试页左下角查看各节点执行详情（或应用日志），得到当前会话「建Scope」节点的响应体 `scope_id`；然后用 curl 召回该会话记忆：

```bash
curl -s -X POST http://127.0.0.1:8000/v1/context/prepare \
  -H "Content-Type: application/json" \
  -d '{"scope_id":"<scope_id>","query":"承诺","max_bytes":2000}'
```

返回的 `content` 即为该会话被召回的记忆文本，可核对 `[承诺]`、`[帮忙/馈赠]`、`[私事]` 等条目与轮次输入一致。

## 七、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 导入 DSL 提示缺少插件 | 未安装 `langgenius/openai` | 「插件」页搜索 openai 安装；或改「老钟回复」节点模型为自己已配置的模型 |
| LLM 节点报"模型不可用" | 模型 API Key 未配/欠费 | 在「设置 → 模型供应商」检查 Key 与连通性 |
| HTTP 节点报连接失败 | PowerContext 未启动或地址不对 | 检查 `curl http://127.0.0.1:8000/health/live`；确认环境变量 `POWERCONTEXT_URL` 与 Server 地址一致 |
| 老钟回复里没有"记忆引用" | ① 不是同一会话（中途开了新会话）② 模型被要求不提及记忆 | ① 全程在同一「新会话」中连续对话 ② 回复规则允许引用；若多次不引用可降低 temperature |
| 端口 8000 被占用 | 旧进程残留 | 结束占用进程后重启 `powercontext server run` |

## 八、已知限制与配置占位说明

1. **平台**：PowerContext 在 Windows 上为 experimental 支持，推荐 Linux / WSL2 运行 Server；Dify 无此限制。
2. **事件提取**：采用关键词规则（DSL 内 Code 节点），复杂/隐晦句式可能归类不准确，但不影响记忆写入与召回主流程。
3. **鉴权**：默认无鉴权部署仅用于本地体验与评测；公网部署请开启 PowerContext Server token 鉴权，并把 token 填入环境变量 `POWERCONTEXT_TOKEN`（DSL 已预留）。
4. **模型成本**：LLM 调用消耗用户自备模型额度；建议 gpt-4o-mini / deepseek-chat 等低价模型。
5. **配置占位**：本文所有 API Key 均以 `<你的API_KEY>` 占位，未提交任何真实凭据；工作流内 PowerContext 地址为默认本地值，可按实际环境修改 `POWERCONTEXT_URL`。
