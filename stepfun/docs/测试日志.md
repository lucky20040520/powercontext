## 1. 测试条件（固定）

- 设备/浏览器：Windows 11 · Chrome（WebGPU 可用）· 同一会话
- 后端：seekdb 嵌入式 v1.4.0.0（引擎 `5.7.25-OceanBase seekdb-v1.4.0.0`），database `kb`，collection `docs` / `eval`（HNSW cosine + IK 全文索引）
- 模型：bge-small-zh-v1.5（512 维，中文，Xenova ONNX 转换版）、all-MiniLM-L6-v2（384 维，英文，Xenova ONNX 转换版）
- 精度：FP32（`model.onnx`）/ FP16（`model_fp16.onnx`）/ INT8（`model_quantized.onnx`，Q8 动态量化）
- 推理后端：WebGPU（`navigator.gpu` 探测）/ WASM（强制降级）
- 数据：中文集 72 篇 / 20 查询；英文集 24 篇 / 10 查询；写入批 100，向量化批 16

## 3. 关键观测

1. **量化质量**：INT8 + WASM 与 FP32 基线质量一致（中文 95.0/92.8 完全相同）；INT8 + WebGPU 纯向量路显著退化（中文 12.5%，英文 5.0%），混合路仍保持 92.5% / 80.0%。
2. **后端吞吐**：WebGPU 为 WASM 的 4~7 倍（中文 FP32：85.4 vs 13.6 doc/s）；INT8 在 WebGPU 因算子回退反而低于 FP16/FP32，在 WASM 上最快且质量无损。
3. **seekdb 检索**：4~7 ms 稳定（与精度/模式/规模无关），混合与向量无显著差异。
4. **端到端查询**：17~26 ms（正常组合）；INT8+WebGPU 因查询向量化（77~102 ms）拉高到 86~110 ms。
5. **首/次加载**：首次加载含模型文件传输（本机缓存后 90~400 ms 级）；`data/eval-log-final.json` 中 `loaded` 字段为浏览器缓存命中后的实测。

## 4. 复现方法

1. 按 `docs/运行说明.md` 启动（模型 → 后端 → 前端）。
2. 打开 `http://127.0.0.1:3000/`，页面底部评测面板：
   - 单组：选模型/精度/后端 →「运行评测（当前模型/精度/后端）」。
   - 全矩阵：勾选/取消「强制 WASM」控制后端集合 →「一键评测全矩阵」，自动跑 2×3×2 共 12 组。
   - 导出：点「导出本次评测原始数据（JSON）」获得与 `data/eval-log-final.json` 同构的原始数据。
3. 对照组（单一变量）：仅改变精度或仅改变后端，其余（模型、评测集、K、重复次数、批次）保持不变。

## 5. 附加环境日志（开发期诊断，供评审参考）

- seekdb-js 嵌入式链路冒烟（建库→建集合→显式向量 add→refresh→query/hybrid 命中）：`server/spike-seekdb.js` 可复跑。
- 首次建 HNSW 索引超时（`ret=-4012`）已通过连接后 `SET SESSION ob_query_timeout=600000000` 解决，后端自动执行。
- npm 依赖坑：`seekdb@1.4.0` 可选 peer 发布缺陷（`workspace:*`）→ `server/.npmrc` 的 `legacy-peer-deps=true`。
