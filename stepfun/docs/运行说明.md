# 运行说明：从零复现到完成评测

> 适用：Windows / Linux / macOS，Node.js ≥ 18（建议 20+），Chrome / Edge 最新版
> 全程无云端推理：模型文件下载、向量化、检索都在本机/浏览器完成

## 0. 环境与依赖

| 依赖 | 版本（本项目实测） | 说明 |
|---|---|---|
| Node.js + npm | Node 22 / npm 10 | 运行 seekdb 嵌入式后端与前端构建 |
| Python 3 | 3.13 | 运行模型准备脚本（也可手动下载模型） |
| Chrome / Edge | 最新版 | 需支持 WebGPU（Chrome 113+） |

## 1. 获取代码与模型

```bash
git clone https://github.com/lucky20040520/powercontext.git   # 或评审镜像仓库
cd powercontext
git checkout 2026-competition-ecosystem
cd stepfun
```

**模型准备**（生成 `models/`，含 fp32/fp16/int8 三档 × bge-small-zh-v1.5、all-MiniLM-L6-v2）：

```bash
python scripts/prepare_models.py            # 默认源 hf-mirror.com（国内可达）
# 可选：HF_ENDPOINT=https://huggingface.co python scripts/prepare_models.py
# 可选：--model bge-small-zh-v1.5 --variant fp16 单模型单档下载
```

脚本会下载每个变体的 `config.json / tokenizer.json / tokenizer_config.json / special_tokens_map.json / vocab.txt / onnx/model*.onnx`，计算 SHA-256 并写入 `docs/模型清单.json`。已存在的文件自动跳过（断点续传语义）。**模型文件约 320 MB，不入 git。**

## 2. 启动后端（seekdb 嵌入式）

```bash
cd stepfun/server
npm install        # 首次会下载 seekdb 原生绑定（js-bindings win32-x64）
npm start          # 监听 http://127.0.0.1:3000
```

- `.npmrc` 已配置 `legacy-peer-deps=true`：规避 npm 解析 seekdb 可选 peer `@seekdb/default-embed` 历史发布缺陷（`EUNSUPPORTEDPROTOCOL workspace:*`）。本应用不使用服务端默认嵌入，向量由浏览器显式传入（`embeddingFunction: null`），符合题目"向量化必须在用户设备完成"。
- 启动日志应出现：`database=kb default_collection=docs engine=5.7.25-OceanBase seekdb-v1.4.0.0`、`frontend at http://127.0.0.1:3000/`。
- 嵌入式数据目录默认为 `stepfun/server/data/`（运行时生成，不入库）。**如需把引擎数据放到其他磁盘/路径**（例如 C 盘紧张时迁移到 D 盘），设置环境变量 `SEEKDB_DB_PATH` 指向目标 `.db` 目录即可，例如：
  ```bash
  # PowerShell
  $env:SEEKDB_DB_PATH = "D:\devcache\powercontext\server-data\seekdb.db"; npm start
  # bash
  SEEKDB_DB_PATH=/d/devcache/powercontext/server-data/seekdb.db npm start
  ```
  注意：seekdb 嵌入式引擎对 Windows junction（目录联接）数据路径存在初始化挂起问题，自定义路径请使用真实目录而非 junction。后端还静态服务 `app/dist/`（前端）、`models/`（模型）、`data/eval/`（评测集）、`data/corpus/`（示例语料）。

## 3. 构建前端（如直接使用提交的 `app/dist/` 可跳过）

```bash
cd stepfun/app
npm install
npm run build      # 产出 dist/，并在 dist/wasm 拷贝 onnxruntime-web 的 wasm 资产
```

## 4. 打开应用并完成全流程

浏览器访问 `http://127.0.0.1:3000/`：

1. **确认后端与推理后端**：顶栏徽章显示 `seekdb：5.7.25-OceanBase seekdb-v1.4.0.0`、`后端：WEBGPU`（WebGPU 可用时）。
2. **加载模型**：默认 bge-small-zh-v1.5 / FP32 基线 / WebGPU，点「加载模型」，显示加载与预热耗时、维度。
3. **导入语料**：点「导入示例语料（中文 72 篇）」载入示例 → 点「开始导入」：浏览器本地批量向量化 → 写入 seekdb → 索引刷新，进度条与分阶段耗时实时显示。
4. **混合检索**：输入查询（如"向量数据库的 HNSW 索引是怎么工作的"）→ 选「混合检索（向量+全文 RRF）」→ 搜索：返回 RRF 分数排序结果，状态行显示查询向量化 / seekdb 检索 / 端到端耗时与全文条件。
5. **增量写入验证**：再粘贴一段新文本导入 → 立即用其中关键词检索，新内容可命中（refresh_index 已生效）。
6. **降级路径验证**：勾选「强制 WASM（模拟降级环境）」→ 徽章变 `后端：WASM（强制）`→ 重新加载模型后重复第 3-4 步，核心流程仍可运行。

## 5. 运行评测（生成质量与性能数据）

评测面板（页面底部）：

- **单组评测**：当前模型/精度/后端，K=5，热查询重复 3 次 → 输出 Recall@5 / nDCG@5（混合与纯向量两路）+ 分阶段耗时（加载/预热、向量化吞吐、写入、索引刷新、查询向量化、seekdb 检索、端到端）。
- **一键评测全矩阵**：自动跑 2 模型 × 3 精度 ×（WebGPU + WASM）共 12 组，逐组写入结果表（每组约 1-4 分钟，WASM 慢于 WebGPU）。
- **导出原始数据**：`导出本次评测原始数据（JSON）` 下载完整 JSON（含逐查询明细）。本仓库已附实测结果：`data/eval-log-final.json`（评审可直接查看，无需重跑）。

## 7. 故障排查

| 现象 | 处理 |
|---|---|
| `npm install` 报 `EUNSUPPORTEDPROTOCOL workspace:*` | 确认 `server/.npmrc` 含 `legacy-peer-deps=true`（已随仓库提供） |
| 原生绑定下载慢/失败 | 预下载 zip 至 `~/.seekdb/bindings/<commit>/win32-x64/`，或用 `SEEKDB_BINDINGS_BASE_URL` 指向镜像（详见 seekdb-js 文档） |
| 检索返回超时 `ret=-4012` | 首次建 HNSW 索引超时；后端启动时已 `SET SESSION ob_query_timeout=600000000`，无需处理 |
| 新导入内容检索不到 | 写入后必须等 `refresh_index()` 完成（前端已自动调用，日志可见 refreshMs） |
| 模型加载 404 | 确认 `models/` 已生成且目录结构为 `models/<模型>/<精度>/{config.json,tokenizer.json,onnx/*}` |
| WebGPU 徽章显示但加载慢 | 确认浏览器开启 WebGPU；显卡不支持时建议使用 WASM 组合（INT8 + WASM 质量无损且更快） |
