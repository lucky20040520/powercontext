# 一页技术说明：端侧向量化 × seekdb 混合检索迷你知识库

> 题目：端侧 AI 推理性能优化与 seekdb 混合检索（PowerContext 2026 · seekdb × 阶跃星辰）
> 实测环境：Windows 11 · Chrome（最新版，WebGPU 可用）· Node 22 本地嵌入式 seekdb v1.4.0.0 · 中文评测集 72 篇 / 20 查询，英文 24 篇 / 10 查询 · 全部计时为浏览器/服务端实测，热查询重复 3 次取中位数

## 1. 模型与量化

| 模型 | 来源与版本 | 维度 | 语言 |
|---|---|---|---|
| bge-small-zh-v1.5 | BAAI 开源 → HuggingFace `Xenova/bge-small-zh-v1.5`（ONNX 转换版，权重 SHA-256 见 `docs/模型清单.md`） | 512 | 中文 |
| all-MiniLM-L6-v2 | sentence-transformers 开源 → HuggingFace `Xenova/all-MiniLM-L6-v2`（ONNX 转换版，与 seekdb 官方示例同款） | 384 | 英文 |

**量化方案**：直接采用官方发布的三档 ONNX 变体，不做自行动态量化——FP32 基线 `model.onnx`、FP16 `model_fp16.onnx`、INT8 `model_quantized.onnx`（Q8 动态量化）。前端按精度加载对应文件（fp16 → WebGPU 原生半精度算子；int8 → 小体积 + 低精度推理）。

**体积与压缩比（实测文件大小，SHA-256 见模型清单）**：

| 模型 | FP32 | FP16 | INT8(Q8) | 压缩比 FP16 | 压缩比 INT8 |
|---|---|---|---|---|---|
| bge-small-zh-v1.5 | 94,851,877 B | 47,497,427 B | 24,010,842 B | 1.997× | 3.95× |
| all-MiniLM-L6-v2 | 90,387,606 B | 45,297,825 B | 22,972,370 B | 1.996× | 3.94× |

**检索质量变化（Recall@5 / nDCG@5，混合检索与纯向量两路分别对比）**：

| 配置 | 中文混合 | 中文向量 | 英文混合 | 英文向量 |
|---|---|---|---|---|
| FP32 基线 WebGPU | 95.0% / 92.8% | 82.5% / 81.0% | 90.0% / 78.9% | 90.0% / 92.3% |
| FP16 + WebGPU | 92.5% / 91.3% | 82.5% / 80.8% | 90.0% / 78.9% | 90.0% / 92.3% |
| INT8(Q8) + WebGPU | 92.5% / 89.2% | **12.5% / 10.2%** | 80.0% / 72.3% | **5.0% / 3.9%** |
| INT8(Q8) + WASM | **95.0% / 92.8%（无损）** | 82.5% / 81.0% | 90.0% / 78.2% | 90.0% / 92.3% |

**结论（实测）**：FP16 在两个后端质量与 FP32 基本一致（中文混合 -2.5pp / 英文持平）；INT8 在 **WASM 后端几乎无损**（中文混合与基线持平），但在 **WebGPU 后端纯向量路显著退化**（中文 82.5%→12.5%、英文 90%→5%）——原因是 Q8 动态量化模型的算子在该环境部分回退到 CPU 且数值精度受损；此时**混合检索仍保持 92.5% / 80.0%**，全文路 + RRF 融合有效兜底。这既是量化质量差异的实测证据，也验证了"混合检索 ≥ 纯向量"的工程结论。

## 2. 端侧运行与后端降级

- **运行时**：`@huggingface/transformers` 3.8.1（内置 onnxruntime-web 1.22.0-dev），`pipeline("feature-extraction", …)` 在浏览器本地执行 embedding，无任何云端推理 API；文档与查询向量均在本机计算（网络请求只涉及模型文件下载与本地 seekdb 服务）。
- **WebGPU 选择方式**：`navigator.gpu.requestAdapter()` 探测；可用时 `device: "webgpu"` 显式配置推理后端，并在顶栏徽章显示 `后端：WEBGPU`。
- **WASM 降级策略**：探测失败或用户勾选"强制 WASM"时自动降级为 `device: "wasm"` + `env.backends.onnx.wasm.wasmPaths = "/wasm/"`（构建时随前端产物本地化 ort wasm 资产），界面徽章显示 `后端：WASM（强制）`。**两条路径均已实测跑通完整流程**（导入、检索、评测），数据见第 4 节与 `data/eval-log-final.json`。

## 3. seekdb 使用

- **部署**：嵌入式模式（seekdb-js + 原生绑定 `@seekdb/js-bindings`，Node 进程内运行引擎）；database `kb`，collection `docs`（评测用独立 `eval` 集合，互不污染）。
- **表结构 / 索引配置**（Schema API）：向量索引 `VectorIndexConfig("hnsw", { dimension: 512/384, distance: "cosine", embeddingFunction: null })`（向量由浏览器显式传入，不在服务端推理）；全文索引 `FulltextIndexConfig("ik", { ik_mode: "smart" })`（中文 IK 分词，英文同样适用）。文档原文存 `document` 列，元数据（文件名、分块序号）存 `metadata` 列。
- **混合检索**：单次 `collection.hybridSearch({ query: { whereDocument: { $contains: 关键词 } }, knn: { queryEmbeddings: 查询向量 }, nResults, include })` 由 seekdb 引擎一次性完成全文匹配（`MATCH(document) AGAINST(? IN NATURAL LANGUAGE MODE)`，引擎内 IK 分词）+ 向量 ANN + RRF 融合排序，**不在客户端拼合两路结果**。另提供纯向量 `query()` 模式用于对比。
- **增量写入与索引刷新**：批量 `collection.add({ ids, documents, metadatas, embeddings })` 后调用 `collection.refresh_index()`（底层 `CALL dbms_index_manager.refresh()`，连接初始化时 `SET SESSION ob_query_timeout=600000000` 规避首次建 HNSW 索引超时）；刷新完成后新文档立即可被向量与混合检索命中（实测：连续增量导入中文文档 → 刷新 → 检索命中，见 `docs/验证记录.md`）。

## 4. 状态管理与性能优化（实测对比）

- **集合 / 会话状态**：`docs` 与 `eval` 集合相互独立；会话记忆（模型/精度/后端选择）存 localStorage，刷新页面后保持；导入采用"向量化一批 → 写入一批"流水线，进度实时显示；支持清空重建（drop + recreate）保证演示环境干净。
- **优化点**：① 向量化批处理（默认 16 篇/批，输入可调）；② 写入批量 100 条 + 单次 `refresh_index()`（避免逐条刷新）；③ WebGPU 优先（吞吐为 WASM 的 4~7 倍）；④ 模型文件本地化 + 浏览器缓存，二次加载毫秒级；⑤ 热查询复用已加载模型，评测报告中位数而非单次最优。
- **关键性能对比（中位数，中文集）**：

| 配置 | 向量化吞吐 | 向量化(72篇) | 写入+刷新 | 查询向量化 | seekdb 检索 | 端到端查询 |
|---|---|---|---|---|---|---|
| FP32 + WebGPU | 85.4 doc/s | 844 ms | 636 + 213 ms | 9 ms | 6 ms | 19 ms |
| FP16 + WebGPU | 94.0 doc/s | 766 ms | 503 + 303 ms | 8 ms | 6 ms | 17 ms |
| INT8 + WebGPU | 19.9 doc/s | 3.61 s | 831 + 213 ms | 77 ms | 7 ms | 86 ms |
| FP32 + WASM | 13.6 doc/s | 5.28 s | 653 + 312 ms | 18 ms | 6 ms | 26 ms |
| INT8 + WASM | 22.7 doc/s | 3.17 s | 669 + 316 ms | 13 ms | 6 ms | 22 ms |

**结论（实测）**：WebGPU 相对 WASM 向量化吞吐提升约 4~7 倍；seekdb 混合检索延迟稳定在 4~7 ms（与数据规模、模式无关）；INT8 在 WebGPU 下因算子回退反而更慢，在 WASM 下体积小、质量无损、吞吐优于 FP32-WASM，是低配设备的推荐组合；FP16 + WebGPU 是质量/速度/体积综合最优。完整 12 组数据（含英文集与逐查询明细）见 `data/eval-log-final.json`。
